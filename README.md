A comparative study of full-stack authentication system implementations generated by various AI coding assistants. This repository serves as a benchmark to analyze architectural patterns, security implementations, and coding styles across different AI tools.

## 📂 Repository Structure & Implementation Details

Each directory contains a complete implementation of an authentication system (Frontend + Backend) generated by a specific AI tool. Below is a detailed breakdown of the unique characteristics of each:

### 🤖 [GitHub Copilot](./copilot)
*   **Philosophy:** Minimalist and direct. Focuses on the "happy path" with standard library implementations.
*   **Key Features:**
    - Single-file backend logic (`index.js`).
    - Standard `bcrypt` and `jsonwebtoken` usage.
    - Simple `localStorage` token management on the frontend.
*   **Best For:** Understanding the bare-metal flow of JWT authentication.

### 🤖 [Cursor](./cursor)
*   **Philosophy:** Modern DX (Developer Experience) with strong type safety and validation.
*   **Key Features:**
    - **Validation:** Uses `zod` for strict schema validation of API requests.
    - **Database:** Implements `sql.js` for a unique JavaScript-centric SQLite interface.
    - **State:** Structured `AuthContext` with explicit loading and error states.
*   **Best For:** Developers looking for a modern, type-safe implementation.

### 🤖 [Gemini (Google)](./google)
*   **Philosophy:** Full-featured, polished, and production-ready UI/UX.
*   **Key Features:**
    - **Frontend:** React 19 + Tailwind CSS for a modern "glassmorphic" design.
    - **UI Polish:** Includes Lucide icons and smooth CSS transitions.
    - **Documentation:** Extremely detailed internal READMEs and fix logs.
*   **Best For:** Seeing how AI handles modern styling and comprehensive project documentation.

### 🤖 [Qoder](./qoder)
*   **Philosophy:** Classic, clean, and reliable implementation.
*   **Key Features:**
    - Custom middleware for input validation without heavy external libraries.
    - Standard React Context API pattern for global auth state.
    - Clean separation of database operations in `database.js`.
*   **Best For:** Understanding core Node/React patterns without dependency bloat.

### 🤖 [Trae](./trae)
*   **Philosophy:** ByteDance's approach—efficient and modular.
*   **Key Features:**
    - Uses `bcryptjs` for a dependency-free (pure JS) hashing solution.
    - Clean API client implementation in `frontend/src/api.js`.
    - Explicit regex-based input validation on the backend.
*   **Best For:** A balanced implementation with minimal external dependencies.

### 🤖 [Warp](./warp)
*   **Philosophy:** Architectural excellence and security best practices.
*   **Key Features:**
    - **Modularity:** Separate modules for `auth.js`, `db.js`, and `validation.js`.
    - **Security:** Uses `express-validator` for robust sanitization and validation.
    - **UI:** Includes a custom `PrivateRoute` wrapper and dedicated CSS modules.
*   **Best For:** Learning about modular backend architecture and professional route guarding.

## 🏗️ Core Tech Stack

Despite variations in implementation, all projects share a common architectural foundation:

- **Backend:** Node.js, Express.js
- **Frontend:** React (Vite/CRA)
- **Database:** SQLite (Local file-based)
- **Authentication:** JSON Web Tokens (JWT)
- **Security:** Bcrypt (Password hashing)

## 🚀 Getting Started

To explore any specific implementation:

1.  Navigate to the desired AI's directory (e.g., `cd google`).
2.  Follow the instructions in the local `README.md` found within that folder.
3.  Typically, you will need to run `npm install` and `npm start` (or `npm run dev`) in both the `frontend` and `backend` directories.
